# OIP-008.5 — Independent device inventory

Inventory placement is `Organization → Infrastructure → Site → Device`. Collection remains `Site → Source → (existing DeviceId, EntityId)`. A device may have **zero** collectors; no placeholder source, protocol installation, IP probe or agent is needed. Current source_placements retains its one-source-per-device uniqueness to preserve the existing contract; the API represents associations as a list but multiple collectors per device are not yet implemented.

`DeviceRegistration {id:DeviceId, display_name, device_type, site_id, metadata}`. IDs are stable global typed identities, never permission prefixes or names. The operator frontend assigns UUIDv4 unless an explicit ID is supplied. Organizational parents resolve through the actual registered Site; clients cannot forge a separate Organization or Infrastructure field. Current types: server, desktop, laptop, single_board_computer, network_device, industrial_device, sensor, other. No type/manufacturer/OS is inferred from a name.

Metadata supports optional manufacturer/model/operating_system/hostname/IP/MAC/serial/description/tags/physical_location/notes. It contains **no credentials**. Names are 1–128 UTF-8 bytes, nonblank/no control characters; text fields are bounded256 or1024 bytes, max16 unique nonblank tags of32 bytes; IP/MAC syntax is checked. Hostname/text is not a resolved or verified target. Imported metadata is operator assertion, not observation evidence.

`InventoryRecord` adds registration Registered/Archived, origin ManualOperator/ExistingSimulationSource/ExistingExternalSource, nullable created_ms/updated_ms/registered_by and revision. Original source-derived records preserve unknown original times/actors as null. Registered-by is redacted without platform management authority. Manual registrations have actual creation time and selected policy principal; the local OS operator authority is separately recorded in the write audit.

`InventoryDevice` adds resolved organization/infrastructure, actual source IDs, connectivity, telemetry, health and nullable monitoring_simulated. Registration never means online. **Current device connectivity is always Unknown**: an OPC server endpoint's reachability does not prove a host or downstream device is reachable. Source Health remains independently available. Telemetry is NoCollector, CollectorConfigured, Receiving, Stale or Unknown, based on associations and actual runtime data. Health is NotEvaluated; no green NoFinding is fabricated. No interpolation or default numeric values.

monitoring_simulated is false for no monitoring, derived from actual SourceHealth provenance in a live runtime, and **null** for offline associated-source queries without that runtime provenance. Null is not false. Device registration provenance and sample provenance are separate: a manual fixture can be explicitly associated to a simulation source without changing its registered identity or claiming real measurements.

Mutations are typed Register/Update/Archive actions inside an InventoryAdministration batch, protected by **InventoryManage**, separate from DevicesRead. Plans validate all target sites/IDs/revisions centrally before write. Register is idempotent only for the identical existing active registration; conflicts never overwrite. Update is a full replacement with required metadata and expected_revision; the operator helper merges requested fields with the current record first. Site/ownership moves are explicitly unsupported, even for Platform operators; physical_location metadata may change. Archive retains all records/history and does not disable an associated collector. Restore/delete are not implemented.

The fixed supported registry bound is2048 records, at most100 actions per batch and100 results/page. Offset max1000000, deterministic ID ordering, has_more only within the authorized filtered result. No global total or tenant-wide hidden counter is returned. Scope/identity changes require cache invalidation. Snapshot reads and offline changes require a runtime restart to refresh the running immutable inventory view.
