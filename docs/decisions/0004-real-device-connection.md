# ADR 0004 — Registered is not connected

Status: implementation workstream on49a86bb, separate Core and Flutter worktrees; no OIP009 payload overwritten. One integration authority, no main changes/push. Real schema6 database backed up; existing Raspberry-Pi UUID/revision retained. Private endpoint remains unconfirmed and will not be contacted.

Inventory-only registration remains explicitly available and is not successful connection onboarding. Real SSH uses system OpenSSH, pinned host keys, public-key authentication through server-provisioned identity profiles, fixed read-only Linux/macOS queries, bounded subprocesses and output, no UI-supplied shell commands/private key paths. Unknown host keys require explicit consent before authentication; changed bindings are blocked. A second operator confirmation of actual observed identity is required before binding to existing/new inventory. The existing UUID uses CAS and is never inferred from display name.

Browser login uses a short-lived, single-use code issued over authenticated local IPC by an explicit operator CLI. Long-lived IPC credentials never enter the browser. Host-only HttpOnly SameSite=Strict session cookie, bounded expiry/maps, server-bound Principal, Origin checks and separate in-memory CSRF header protect mutations. No token in URL/assets/LocalStorage; no caller Principal or grants. OIP009 context can supply hierarchy IDs to the scoped wizard; no competing global infrastructure selector is added here.

Online inventory/binding/control mutations travel through CapabilityService authorization and the existing bounded writer channel, never a second SQLite writer. Registry snapshots refresh centrally after commit for REST/MCP/SSE. SSH sources are External, first-class source placements bound to a real Device/Site, with the existing observation/event/health pipeline. A bounded runtime supervisor owns at most one collector/device, polls only when explicitly enabled and resumes on restart; source freshness follows configured cadence. Recovered samples remain stale until actual new reads.

Read APIs/MCP share contracts. Mutating MCP tools stay absent. Configuration/probe/host-key acceptance/identity confirmation/control require InventoryManage for the target Site; TelemetryRead gates facts. Local identity profiles are administrator-provisioned, scope-restricted, never arbitrary client file access. No passwords/root login/remote install/privileged commands/proxy commands/network scanning.

Evidence will distinguish automated real SSH loopback fixture from physical Raspberry-Pi acceptance. No physical SSH or monitoring verdict without explicitly confirmed endpoint/user/identity and operator identity confirmation. No production OT or remote-identity certification; existing Advisories/same-UID/durable-audit limits remain.
